# AIOS 业务域地图

本文件用于检索路由，不单独证明某个正式版本支持某项能力。版本相关结论必须继续查询正式资料和 CodeContext。

## 主要业务域

| 业务域 | 关键对象 | 首查方向 |
|---|---|---|
| 模型仓库 | 系统模型、自定义模型、模型权重 | Model Center、模型元数据、文件存储 |
| 数据集 | 精调和评测数据 | 数据集记录、文件路径、挂载链路 |
| 模型精调 | 精调任务、训练后模型记录 | 后端任务、运行实例、GPU 和数据集 |
| 推理模板 | 框架、启动参数、资源要求、模型匹配 | 模板定义、`service.yaml`、应用包 |
| 推理服务 | VM 或容器实例 | 前端入口、后端 API、AIOS 应用、节点日志 |
| 服务评测 | 性能评测、能力评测 | 评测任务、数据集、推理服务、指标 |
| 应用开发服务 | Dify、FastGPT、MaxKB、ComfyUI 等 | `aios/applications` 和后端资源编排 |
| 资源统计 | 推理、评测、精调实例资源 | 资源查询 API 和前端统计页 |
| 平台配置 | Model Center 和模型平台参数 | 配置 API、Model Center 服务 |

## 推理服务形态

- VM 推理：推理框架和业务服务运行在 AIOS 云主机中。
- 容器推理：推理框架运行在 Kubernetes/容器环境中。

创建、页面入口和状态问题通常需要联合检查：

```text
zstack-ui-next 页面与权限条件
→ zstack/premium API 与资源状态
→ zstack-utility 节点侧动作
→ aios 应用包、启动配置和运行服务
```

## Model Center

Model Center 管理模型文件、推理模板、推理代码和数据集。常见组件线索：

- `model-center-agent.service`：管理和内容入口。
- `zstack-dfs.service`：文件服务或数据链路线索。
- Nginx、Filebrowser：访问和文件管理入口。
- Redis、JuiceFS、NFS、virtiofs：按版本和部署形态参与数据路径。

组件名称只用于定位；实际版本的数据链路必须从对应版本资料与源码确认。

## VM 推理运行时

常见排障链路：

```text
管控侧生成配置
→ VM 获得 service.yaml 或等价元数据
→ 系统服务翻译运行环境
→ 准备模型、代码和数据集
→ run.sh / app.sh
→ 推理框架进程
→ 对外 API 与健康检查
```

常见日志和端口线索：

- `/var/log/ai/startup.log`：启动阶段。
- `/var/log/ai/app.log`：应用运行。
- `/var/log/ai/access.log`：访问日志。
- `3000`：常见服务入口。
- `3001`：常见内部应用端口。
- `8888`：JupyterLab。

路径和端口可能随版本或应用变化，给出现场命令前必须查对应版本或先只读定位。

## 问题路由

| 现象 | 优先查证 |
|---|---|
| 页面没有菜单或按钮 | `zstack-ui-next` 权限/能力条件，后端 API 是否存在 |
| 创建后长时间未知 | 后端资源状态、任务链路、AIOS 启动日志 |
| 模型文件不可见 | Model Center、文件元数据、存储数据面 |
| 推理框架无法启动 | 模板参数、应用包、GPU/驱动、启动日志 |
| API 可达但请求失败 | 网关/代理、内部框架端口、应用日志 |
| VM 与容器表现不同 | 分别查询两条部署链路，禁止类推 |
| 版本升级后行为变化 | 生成两个独立 CodeContext 后做代码与资料对比 |
